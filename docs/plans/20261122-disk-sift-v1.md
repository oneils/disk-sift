# DiskSift v1: app uninstaller and junk cleaner for macOS

## Overview
- DiskSift is a personal macOS GUI app in the spirit of AppCleaner / CleanMyMac:
  1. **Uninstall**: drag a `.app` from `/Applications` or `~/Applications` into the window; DiskSift finds its leftovers (preferences, caches, containers, launch items, pkg receipts), shows them with a confidence level, unloads its launch agents and moves the app plus the checked leftovers to the Trash.
  2. **Junk cleanup**: scan user caches/logs and developer junk (Xcode, Homebrew, npm, pip, cargo, go), show sizes per category and permanently delete what is checked.
- No background agent, no App Store, no sandbox. Phase 1 is ad-hoc signed for personal use; Developer ID + notarization may come later and must not require architectural changes.
- Greenfield project in `~/projects/disk-sift`, GitHub repo `oneils/disk-sift` (private).

## Solution Overview
- `Package.swift` (tools 6.0, `.macOS(.v14)`) with targets:
  - `SiftCore` (library, Foundation + Security + Darwin only, no SwiftUI/AppKit): scanning, matching, sizing, removal, uninstall ordering
  - `DiskSift` (executable, SwiftUI + AppKit): windows, `@Observable` view models, drag & drop, live `RunningApps`/`InstalledApps` (NSWorkspace)
  - `SiftCoreTests`, `DiskSiftTests`
- Every path comes from an injected `SiftPaths` (not `Environment`: that name clashes with SwiftUI's `@Environment`), so the whole core runs against temp-dir fixtures.
- Extension points are protocols: `LeftoverSource` (a known-paths DB can be added later as one more source), `JunkCategory`.
- **Safety lives in `Remover`, not the UI**: removal is allowed only strictly inside an explicit list of roots derived from the same constants the scanners use; paths are canonicalized; symlinks are never followed; root-only items are never attempted; writability is rechecked at removal time.
- **Uninstall order lives in `Uninstaller`**: unload user launch agents → trash the app → trash leftovers; if the app can't be trashed nothing else is touched.
- Localization: English source strings as keys, `Resources/{en,ru}.lproj/Localizable.strings` + `Localizable.stringsdict` (Russian plurals) copied into `Contents/Resources` by `make-app.sh` and read through `Bundle.main` (SwiftPM resource bundles for executables end up in the `.app` root and break code signing; `.xcstrings` needs Xcode to compile). `swift run` without a bundle falls back to the English keys.

### Core types
```swift
struct SiftPaths: Sendable { home, library, systemLibrary, applications, userApplications, tmp: URL; static let live }
protocol CommandRunner: Sendable { func run(_ exe: String, _ args: [String]) async throws -> CommandResult }  // stdout, stderr, status
protocol InstalledApps: Sendable { func isInstalled(bundleID: String, excluding: URL) -> Bool }
protocol RunningApps: Sendable { func running() -> [RunningApp] }  // bundleID, bundleURL, pid
enum Confidence: Int, Comparable, Sendable { case low, medium, high; static func < ... }
enum FindingSource: Hashable, Sendable { libraryPath, groupContainer, launchItem(label: String, domain: LaunchDomain), pkgReceipt, junk(categoryID: String) }
struct Finding: Identifiable, Hashable, Sendable { url, size: Int64?, confidence, sources: Set<FindingSource>, requiresRoot, inaccessible: Bool }
enum RemovalPolicy: Sendable { trash, delete }
struct SigningInfo: Sendable, Equatable { teamID: String?, appGroups: [String], isAppleAnchored: Bool }
struct AppInfo: Sendable { url, bundleID, name, signing: SigningInfo, nestedBundleIDs: [String] }
protocol LeftoverSource: Sendable { func findings(for app: AppInfo, paths: SiftPaths) async throws -> [Finding] }
protocol JunkCategory: Sendable { id, title, policy; func scan(paths:) async throws -> [Finding]; func checkedByDefault(_:running:) -> Bool }
struct RemovedItem: Equatable, Sendable { url, size }
struct SkippedItem: Equatable, Sendable { url, reason: SkipReason }   // outsideRoots, needsAdmin, permissionDenied, inUse, vanished, appNotRemoved
struct RemovalReport: Equatable, Sendable { removed: [RemovedItem], skipped: [SkippedItem] }
```

### Scan locations (single source of truth)
- `ScanLocations.leftoverDirs(paths)`: `~/Library/{Application Support, Caches, Preferences, Preferences/ByHost, Containers, Group Containers, Saved Application State, Logs, HTTPStorages, WebKit, Cookies, LaunchAgents, Application Scripts, Autosave Information}` and `/Library/{Application Support, Caches, Preferences, Logs, LaunchAgents, LaunchDaemons, PrivilegedHelperTools}`.
- `DevJunkCategory.paths(paths)` and `UserCachesCategory.dirs(paths)` are the only other place paths are listed.
- `RemovalRoots` is built from these constants plus `/Applications` and `~/Applications`, so scanners and the remover can't drift apart.

### Matching rules (LibraryPathsSource)
- Only direct children of the leftover dirs are checked; the name is stripped of known extensions (`.plist`, `.savedState`, `.binarycookies`) before matching.
- **high**: name == bundle ID / nested bundle ID, or starts with `<ID>.`; `Group Containers/<group>` where `<group>` is listed in the app's `com.apple.security.application-groups` entitlement.
- **low**: `Group Containers/<TEAMID>.*` not in the entitlement (shared by the vendor's other apps, e.g. Office); name equals the app name case-insensitively, app name ≥ 4 chars (`Arc` ignored, `Code` matched as low).
- **downgrade to low**: any match whose name equals or is prefixed by the bundle ID of *another* installed app (`InstalledApps`), e.g. `com.foo.App.Lite` when uninstalling `com.foo.App`.
- Without Full Disk Access, `Containers` and `Group Containers` are not read at all (avoids a privacy prompt per app); they are reported as inaccessible. `EPERM` is treated like `EACCES`.

### Writability (requiresRoot)
- Deleting or moving an item needs write + search on its parent dir; with the sticky bit set on the parent, the current user must also own the item.
- Moving a *directory* to the Trash additionally needs write on the directory itself (its `..` entry changes).
- Computed by `Writability.canRemove(_:policy:)`; scanners use it to set `requiresRoot`, and `Remover` recomputes it right before acting instead of trusting the flag.

### Merge (FindingMerger)
- dedupe by canonical path; for exact duplicates union sources and take max confidence.
- when a finding has an ancestor that is also a finding, drop the child; the ancestor keeps **its own** confidence (a large low-confidence folder is not promoted by a high child), sources are unioned, `requiresRoot`/`inaccessible` are OR'ed.

### DirectorySizer
- `fts_open` with `FTS_PHYSICAL | FTS_NOCHDIR | FTS_XDEV`, sums allocated size (`st_blocks * 512`), compared to `du -sk` in KiB.
- hard links counted once via one `(dev, ino)` set shared across the whole call (actor or locked set), not per child.
- top-level children sized concurrently in a `TaskGroup` bounded to CPU count; `Task.checkCancellation()` every 1000 entries.
- `EACCES`/`EPERM` on entries → result marked `inaccessible`, partial size kept.
- Reported sizes are allocated bytes; actual space freed can be lower because of APFS clones and local snapshots (shown as a note in the UI/README).

### Canonical paths and removal roots
- `CanonicalPath.of(url)`: `realpath` of the parent dir + `lstat` of the last component (a symlink as the last component stays a link). Roots are canonicalized the same way.
- Comparison is case-insensitive (default APFS) and component-wise (`/a/b` is not inside `/a/bc`).
- A path is allowed only if it is **strictly inside** a root; the roots themselves (`~/Library/Caches`, `/Applications`, ...) are never allowed. Anything else, including `~/Library/Mobile Documents`, `~/Library/CloudStorage`, `Keychains`, `Mail`, `Messages`, is refused.
- Symlinked middle components are resolved by `realpath`, so `~/Library/Caches/X -> ~/Documents` makes `~/Library/Caches/X/sub` resolve outside the roots and be refused.
- The window between `lstat` and removal is accepted for a single-user tool; noted in a code comment.

### Removal
- `.trash` → `Trasher.trash(url)`; `.delete` → `removeItem`.
- Read-only trees (Go module cache): only for `.delete` and only after a permission failure, walk with `fts` (`FTS_PHYSICAL | FTS_XDEV`), skip `FTS_SL` entries, add `u+w` with `fchmodat(..., AT_SYMLINK_NOFOLLOW)`, retry once.
- Per-item errors (`EACCES`, `EPERM`, `EBUSY`, `ENOENT`) → `skipped` with reason; items not removable by the current user → `.needsAdmin`, never attempted.

### Uninstaller
1. `launchctl bootout gui/<uid>/<label>` for checked launch agents in the user domain (through `CommandRunner`; failure is logged, not fatal). System-domain items are root-only and are only shown.
2. Trash the `.app`. On failure: stop, every leftover is reported as `appNotRemoved`, nothing else is touched.
3. Trash checked leftovers via `Remover`.

### AppValidator
- Accepts only a real `.app` directory (not a symlink) located under `/Applications` or `~/Applications` with no bundle ancestor (rejects `Xcode.app/Contents/Applications/...`), not on `/Volumes`, not on an App Translocation path, not DiskSift itself.
- Requires `CFBundleIdentifier`.
- Rejects Apple apps: requirement `anchor apple` (not `anchor apple generic`, so Pages/Keynote stay removable) checked with `kSecCSDoNotValidateResources | kSecCSDoNotValidateExecutable` (full resource hashing takes minutes on Xcode/Office).
- Checks removability up front with `Writability` (app dir + parent): pkg-installed/root-owned apps and App Management denials are reported before scanning ("needs admin, can't uninstall in v1").

### SigningInfo
- `SecStaticCodeCreateWithPath` + `SecCodeCopySigningInformation(kSecCSSigningInformation | kSecCSRequirementInformation)`.
- `SigningInfo.parse(dict)` is a pure function: Team ID (`kSecCodeInfoTeamIdentifier`), app groups from `kSecCodeInfoEntitlementsDict`. Unsigned → empty info.

### PkgReceiptsSource
- `pkgutil --pkgs` → IDs equal to or prefixed by bundle ID / nested IDs.
- `pkgutil --pkg-info` gives `volume` and `location`; absolute path = `volume` + `location` (may be empty) + file, normalized.
- `pkgutil --files` → keep only the top-most existing paths that fall strictly inside a leftover scan dir; everything else (shared vendor dirs, `/usr/local/...`) is ignored.
- Pkg-only findings are **low** and unchecked; most are root-owned and only shown anyway.

### Junk categories
- `UserCachesCategory`: children of `~/Library/Caches` and `~/Library/Logs`, excluding paths owned by `DevJunkCategory`. Unchecked by default: `com.apple.*`, and caches whose name matches the bundle ID of a running app (browsers, Electron apps).
- `DevJunkCategory`: `~/Library/Developer/Xcode/DerivedData`, `~/Library/Developer/Xcode/Archives` (unchecked by default: contains dSYMs), `~/Library/Developer/Xcode/iOS DeviceSupport`, `~/Library/Developer/CoreSimulator/Caches`, `~/Library/Caches/Homebrew`, `~/.npm/_cacache`, `~/Library/Caches/pip`, `~/.cargo/registry/cache`, `~/Library/Caches/go-build`, `~/go/pkg/mod`. Missing paths are skipped silently. Allowed roots include the parent of each (e.g. `~/go/pkg`), so each path itself is removable.
- Deleting unavailable simulators needs `xcrun simctl` (Xcode) → out of scope.

### Full Disk Access
- `FullDiskAccess.isGranted(paths)`: try opening `~/Library/Application Support/com.apple.TCC/TCC.db` for reading (always exists); `EPERM`/`EACCES` → not granted.
- `make-app.sh` signs with `$SIGN_IDENTITY` (default `-`). With a local self-signed code-signing certificate the FDA grant survives rebuilds; ad-hoc grants are tied to the code hash.

### Uninstall flow
drop `.app` → `AppValidator` (location, bundle ID, Apple check, removability) → `AppInfo` → if running (match by bundle ID, `bundleURL` or nested IDs) ask to quit: `terminate()`, wait up to 5 s, offer `forceTerminate()` → `LeftoverScanner` (sources in parallel, merge, size) → list grouped by parent dir; high checked, low unchecked, root items greyed → `Uninstaller` → report.

### Junk flow
Scan → categories in parallel, per-category progress and totals → user unchecks → confirmation with total size → permanent delete → report with skipped items.
